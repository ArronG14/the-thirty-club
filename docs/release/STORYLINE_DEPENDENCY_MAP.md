## Cross-cutting principles and how the system meets them

- **Completed stays completed across tabs and devices:** every state above is server-side (admissions, letters opened, compartments OPENED, entitlements); the device caches only server-confirmed state (ADR-020). The card session (ADR-023) gives each scanning device a member session.
- **Honest fulfilment:** vouchers and Vault gifts have explicit owner fulfilment; nothing marks a real-world service as done without the owner. Placeholder letters cannot send.
- **No unnecessary notifications:** only armed milestones send; one SMS per letter through the policy; the hold remains the master switch.
- **"Nothing more to do":** the Lounge offers one guided destination and the Directory; an explicit "nothing more this evening" line per day is not verified to exist and should be specified with the storyline copy.
- **Owner manual triggers:** every milestone has Trigger now / Hold / Resume / Retry / Edit wording.

## Recommended order (next instruction)

1. Vault per-compartment `opens_at` (+ tests, TEST scenario) — unblocks Thursday and Friday's jackpot.
2. Letter action `link` for the Departure Lounge.
3. Casino `position: 'last'` for the final-spin prizes, and the 14:30 / 20:30 spin milestones.
4. Airport voucher mechanism decision, then the minimal grant path.
5. Wording passes (travel, dinner, farewell), breakfast confirmation, film.

Each is one additive migration or a small UI change on existing infrastructure; none requires a new backend.
